## 🎯 Visão Geral do Sistema

O **Anoteitor** é um sistema de anotações inteligente projetado para:

- ✅ Capturar informações rapidamente no dia a dia
- ✅ Organizar anotações por **projetos** e **subatividades**
- ✅ Proteger contra perda de dados com salvamento automático
- ✅ Manter histórico completo de edições por data
- ✅ Trabalhar offline com arquivos de texto simples (.txt)

---

## 📁 Arquitetura de Arquivos (Working Copy + Histórico)

### Conceito Fundamental: Dois Tipos de Arquivos

| Tipo | Formato | Função | Exemplo |
|------|---------|--------|---------|
| **Working Copy** | `Projeto^Sub.txt` | Arquivo principal de trabalho do dia atual | `GruposWhats^Porto Alegre.txt` |
| **Histórico** | `Projeto^Sub^DD-MM-AAAA.txt` | Snapshot salvo automaticamente ao fechar | `GruposWhats^Porto Alegre^17-03-2026.txt` |

### Fluxo de Criação de Arquivos

```mermaid
graph LR
    A[Iniciar edição no dia 18/03] --> B{Working copy existe?}
    B -->|Sim| C[Editar diretamente no working copy]
    B -->|Não| D[Criar working copy vazio]
    C --> E[Salvar periodicamente no working copy]
    D --> E
    E --> F[Fechar programa]
    F --> G{Working copy foi editado hoje?}
    G -->|Sim| H[Salvar snapshot histórico: ^18-03-2026.txt]
    G -->|Não| I[Não criar snapshot]
    H --> J[Manter working copy para amanhã]
    I --> J
```

### Estrutura de Pastas

```
C:\Anoteitor\
├── [Projeto 1]\
│   ├── [Subatividade 1]\
│   │   ├── Projeto^Sub.txt                 ← Working copy (edição atual)
│   │   ├── Projeto^Sub^15-03-2026.txt      ← Histórico (snapshot do dia 15)
│   │   └── Projeto^Sub^16-03-2026.txt      ← Histórico (snapshot do dia 16)
│   └── [Subatividade 2]\
│       ├── Projeto^Sub2.txt
│       └── Projeto^Sub2^17-03-2026.txt
└── [Projeto 2]\
    └── ...
```

## ✍️ Fluxo de Trabalho Diário

### 1. Abertura do Programa

Ao iniciar o Anoteitor:

1. Sistema carrega automaticamente o **working copy** da última subatividade usada
2. Se working copy não existe:
   - Busca o arquivo histórico **mais recente com conteúdo**
   - Copia conteúdo para novo working copy
   - Abre working copy para edição

### 2. Edição Contínua

Durante o dia:

- ✅ Todas as edições são feitas **diretamente no working copy** (`Projeto^Sub.txt`)
- ✅ Salvamento automático a cada X segundos (configurável)
- ✅ Fundo **branco** indica que você está editando o arquivo do dia atual

### 3. Fechamento do Programa

Ao fechar:

1. Sistema verifica se working copy foi editado **hoje**
2. Se sim → cria snapshot histórico com data atual (`^DD-MM-AAAA.txt`)
3. Working copy permanece intacto para uso no próximo dia

> 💡 **Importante**: O working copy **nunca é sobrescrito** por snapshots históricos. Ele é sempre preservado como arquivo principal de trabalho.

## 📅 Visualização de Datas Históricas

### Como Acessar Conteúdo de Datas Anteriores

1. Clique no combo de datas na interface
2. Selecione a data desejada (ex: "15/03/2026")
3. Sistema abrirá **exatamente** o arquivo daquela data (`Projeto^Sub^15-03-2026.txt`)

### Comportamento ao Selecionar Data Histórica

| Situação | Comportamento |
|----------|---------------|
| **Arquivo da data existe com conteúdo** | ✅ Abre exatamente esse arquivo com fundo **azul** |
| **Arquivo da data existe mas vazio** | ✅ Busca data mais próxima **anterior** com conteúdo |
| **Arquivo da data não existe** | ✅ Busca data mais próxima **anterior** com conteúdo |
| **Nenhum arquivo com conteúdo encontrado** | ✅ Reverte silenciosamente para data anterior (sem mensagem de erro) |

### Edição em Modo Histórico

⚠️ **Atenção crítica**: Ao visualizar uma data histórica:

- Fundo **azul** indica modo de visualização histórica
- Qualquer edição feita será salva no **working copy atual** (não no arquivo histórico)
- O arquivo histórico **nunca é modificado** — snapshots são imutáveis

## 🎨 Sistema de Cores

| Cor | Significado | Condição |
|-----|-------------|----------|
| **Branco** (`SystemColors.Window`) | Working copy do dia atual | Data de modificação = hoje |
| **Azul Bebê** (`Color.AliceBlue`) | Visualização de conteúdo histórico | Data de modificação < hoje |
| **Cinza** | Arquivo antigo visualizado (somente leitura) | Arquivo histórico aberto manualmente |

> 💡 **Dica visual**: Fundo azul = "você está olhando para o passado, não edite aqui". Fundo branco = "você está no presente, edite à vontade".

## 🔒 Proteção Contra Perda de Dados

### Mecanismos de Segurança

| Mecanismo | Descrição | Ativação |
|-----------|-----------|----------|
| **Salvamento automático** | Salva working copy a cada X segundos | Timer contínuo |
| **Salvamento antes de troca** | Salva antes de mudar de subatividade/data | Ao selecionar nova opção |
| **Carregamento de histórico** | Se working copy vazio, busca conteúdo mais recente | Na abertura do programa |
| **Snapshots imutáveis** | Arquivos históricos nunca são sobrescritos | Ao fechar o programa |
| **Migração automática** | Converte arquivos `^current.txt` para working copy | Na primeira abertura |

### Fluxo de Recuperação de Conteúdo

```mermaid
graph TD
    A[Abrir subatividade] --> B{Working copy existe?}
    B -->|Sim| C{Working copy tem conteúdo?}
    B -->|Não| D{Histórico mais recente existe?}
    C -->|Sim| E[Abrir working copy]
    C -->|Não| D
    D -->|Sim| F[Copiar conteúdo para working copy]
    D -->|Não| G[Criar working copy vazio]
    F --> H[Abrir working copy atualizado]
    G --> H
    E --> I[Pronto para edição]
    H --> I
```

## 🔍 Solução de Problemas

### Problema 1: "Tela em branco ao abrir subatividade"

**Causa**: Working copy vazio (apenas 3 bytes de BOM UTF-8) + nenhum histórico com conteúdo

**Solução**:
1. Sistema automaticamente busca conteúdo no histórico mais recente
2. Se encontrar, copia para working copy e exibe
3. Se não encontrar, cria working copy vazio para edição

**Logs para verificar**:
```
⚠️ Arquivo vazio - buscando conteúdo não vazio no histórico...
✅ Conteúdo NÃO VAZIO carregado de: arquivo.txt (X bytes)
✅ Conteúdo salvo no working copy: arquivo.txt
```

---

### Problema 2: "Conteúdo desapareceu após fechar e reabrir"

**Causa**: Salvamento foi feito em arquivo errado (`^current.txt`) em versões antigas

**Solução (v2.7+)**:
1. Sistema agora salva **sempre** no working copy (`Projeto^Sub.txt`)
2. Migração automática de `^current.txt` para working copy na primeira abertura
3. Snapshots históricos são criados apenas ao fechar, se working copy foi editado hoje

**Logs para verificar**:
```
⚠️ Working copy antigo encontrado (^current.txt): arquivo^current.txt
➡️ Migrando para formato correto: arquivo.txt
✅ Migração concluída para: arquivo.txt
```

---

### Problema 3: "Selecionar data histórica não muda o conteúdo"

**Causa**: Método `Open()` redirecionava internamente para working copy

**Solução (v2.14)**:
1. Separação clara: `Open()` para edição diária, `OpenHistoricalFileOnly()` para visualização
2. `OpenHistoricalFileOnly()` abre **exatamente** o arquivo especificado — sem redirecionamento
3. Fundo azul indica claramente que está em modo histórico

**Logs para verificar**:
```
🔍 Tentando abrir arquivo EXATO da data 15-03-2026: ...\arquivo^15-03-2026.txt
✅ Arquivo EXATO encontrado para 15-03-2026
[v2.14] OpenHistoricalFileOnly: ...\arquivo^15-03-2026.txt
✅ Conteúdo histórico carregado (X caracteres)
🎨 Conteúdo histórico carregado com fundo AZUL
```

---

### Problema 4: "Texto todo selecionado ao abrir"

**Causa**: Evento `GotFocus` do TextBox com `SelectAll()` ou `HideSelection = false`

**Solução**:
1. Remover ou comentar handler `controlContentTextBox_GotFocus`
2. Garantir `HideSelection = true` no designer
3. Adicionar no método `LerConteudoArquivo`:
```csharp
controlContentTextBox.SelectionStart = Content.Length; // Cursor no final
controlContentTextBox.SelectionLength = 0;            // Nenhuma seleção
controlContentTextBox.HideSelection = true;           // Seleção invisível sem foco
```

## 🔐 Segurança e Backup

### Proteção de Dados

- ✅ Todos os arquivos ficam localmente no seu computador
- ✅ Nenhum dado é enviado para servidores externos
- ✅ Arquivos são salvos em formato texto simples (.txt)
- ✅ Snapshots históricos são imutáveis (nunca sobrescritos)

### Estratégia de Backup Recomendada

```batch
@echo off
set BACKUP_DIR=D:\Backup\Anoteitor
set SOURCE_DIR=C:\Anoteitor
set DATE=%date:~-4,4%%date:~-7,2%%date:~-10,2%

robocopy "%SOURCE_DIR%" "%BACKUP_DIR%\%DATE%" /MIR /LOG:"%BACKUP_DIR%\backup_%DATE%.log"
```

> 💡 **Dica**: Use OneDrive/Google Drive para sincronizar `C:\Anoteitor` — mantenha versões anteriores habilitadas na nuvem para recuperação de arquivos acidentais.
